# 生成环境、定向包围盒与 SymphoMotion 运动控制

2026-09-11。本文先于本轮代码修改建立。实现、验证结果在末尾补充。

## 1. ENVNAME 修复

当前服务注册 `symphomotion`、`depthpro`、`sam2`，生成模型仅允许 `symphomotion`。前端创建运行配置却仍默认 `base`，导致提交在启动 Slurm 前被 HTTP 422 拒绝。

内置 SymphoMotion 新配置改用 `symphomotion`。连接能力清单新增每个模型的 `environmentNames`，面板据此校验 ENVNAME 并提供可选环境。仅修复内置模型当前草稿中的旧 `base` 默认值；自定义模型、其他用户环境名、历史提交和待确认请求保持原文。后端错误同时给出请求环境与允许环境，禁止以注册 base 为推理环境绕过校验。

## 2. 包围盒与几何契约

用户已确认采用高精度数值近似，必须包含全部点。使用现有 NumPy，以世界轴、PCA 及确定性的多组旋转初始化，在三维旋转空间中逐级减小角步长优化体积。方向极值点构成初始支持集，完整点簇复核后补入遗漏的极值点再优化；最终在全部点上重新求 min/max 并加浮点容差。候选至少保留原 AABB，输出实际算法名，不承诺数学上的全局最优。无需安装 SciPy/Open3D。

关联仍以 `mask.flat[scene.point_ids]` 筛选原有有效点，不额外删除离群点。框必须包含全部所选点，极薄点簇保留可编辑的最小厚度。输出增加框局部坐标系到场景坐标系的单位四元数 `boxQuaternion`（xyzw）；`center` 为场景坐标，`halfExtents` 为框局部轴上的半尺寸。旧结果缺少四元数时按单位旋转读取。

框的固有朝向与用户选择物体正面产生的控制朝向分开保存。物体点使用 `R(t) R(0)^T (p-c0)+c(t)`，框朝向使用 `R(t) R(0)^T R_box`。选择正面只改变操控坐标，不旋转重建原始点或改变拟合体积。前端框面、标签、旋转控制、项目导入校验和导出保持同一约定。已有物体不自动重拟合，避免破坏录制轨迹起点。

## 3. Rendered Frames

面板标题改为“导出SymphoMotion Rendered Frames”。此前“逐帧移动并光栅化物体点云”的方案被本轮需求替代。

每帧按目标相机渲染完整参考场景的原处点云，其中包括物体在首帧位置的点。受控物体的变换点只用于计算投影 2D 框及 OMM 轨迹，不加入 RGB 光栅化输入。将投影点逐轴像素 min/max 得到的红框叠加到场景渲染上。首帧继续使用原始参考图、空洞 mask 全零，与官方 loader 的首帧替换一致。其余空洞 mask 仅描述参考场景的点覆盖，不把框线当作新几何。

manifest 增加新策略标识和版本；历史动态点云导出包仍可下载，但不能不经重新导出就作为本轮新策略填入当前工作流。保持官方文件名称 `render_with_2d_bbox.mp4`、`render_mask.mp4`、`spatialtracker2.npz` 与 CSV 的消费契约。

## 4. 控制开关

用户已确认：有已应用轨迹时自动开启，关闭保留轨迹，仅本次导出／生成忽略，重新开启恢复。无相应有效轨迹时开关关闭且不能启用。项目保存可选 `motionControls` 覆盖值；默认依据有效轨迹推导。由无到有应用轨迹时清除该项旧覆盖使其自动开启，最后一条轨迹移除后自动关闭。物体控制开启时导出已分配的物体（含用户显式设为静止的实例）；未分配实例不静默当作已控制物体。仅静止实例、没有物体运动轨迹时不启用 OMM。

在生成面板输入参数区域提供两个开关，并按状态隐藏/显示专属参数。状态进入项目快照和导出有效性检查；输入编辑和导出共用同一项目状态，刷新/导入/切换保持一致。

相机关闭应表示固定参考视角，而不是任意删除 ControlNet 输入通道。官方 `camera_embedding` 配置会覆盖 CLI，且相机与场景条件共用已训练模块，因此不以 `--disable_camera_embedding` 冒充可独立关闭相机运动。物体关闭时不启用 OMM，也不叠加物体运动框。开关改变后旧条件包需重新导出；不得用旧视频配新开关而导致行为不一致。

Firefox 验证发现四元数重新归一化可能产生约 1e-16 的数值差异。导出快照比较采用结构递归比较：ID、策略、文本、字段集合和数组顺序必须一致，数值允许绝对误差 1e-9；不再以 JSON 字符逐字相等判定运动快照。此容差远小于点云和像素精度，避免刷新后将有效产物误判为过期。来源作业 ID 的校验仍严格匹配。

## 5. OMM 核对

论文 §3.3 的物体轨迹是每个物体 N 帧 × Np 点 × 3 坐标；公式中的 j 是时间帧下标，单帧内部另有采样点维度。固定采样点身份跨帧随物体作刚体运动，不应每帧重新抽样。轨迹需统一到参考相机系，随后轨迹特征与冻结 umT5 的实体文本特征逐元素相加，再通过物体 cross-attention 注入视频生成模型。[论文](https://arxiv.org/html/2604.03723v1#S3.SS3)

固定源码 `bf9af6666c0f8cbb594e64f165be79b44c962763` 的具体实现比论文示意更细：`ObjectTrajectoryEncoder` 使用 float32 PointNet、逐帧线性投影、文本投影及 token×frame 广播相加；此版本没有论文示意中的独立时间降采样器。保留与现有 object_injector 权重匹配的实现，不擅自换网络结构。[官方编码器](https://github.com/grenoble-zhang/SymphoMotion/blob/bf9af6666c0f8cbb594e64f165be79b44c962763/src/models/pcd_controller.py)

本项目导出每帧相机系 `camera_3d_pred_<id>_sampled`，官方 loader 默认通过 `cam_c2w` 转回首帧相机系。需要验证点身份、旋转和平移、相机运动消除、实体提示词对应关系、实际 encoder 与 injector 调用。上游 loader 会捕获坏数据并退回无实体；适配器必须在开启 OMM 时阻止这种静默失效，并记录实际实体数量与张量形状。

## 6. 验证计划
