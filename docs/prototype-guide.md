## 启动

```bash
npm install
npm run dev
```

开发模式打开终端打印的本地地址，默认是 `http://127.0.0.1:5173/`。建议桌面浏览器、键盘和鼠标；页面根据窗口大小调整，窄屏将控制面板排到主视区下方。生产构建使用 `npm run build`，结果在 `dist/`；本节点由后端统一提供页面和 API，入口及令牌说明见 [后端部署](backend-deployment.md)。

## 界面

界面定位为轨迹编辑与研究验证工具。删除“让想象，沿轨迹发生”“YOUR MOTION, IN SPACE”等宣传文案，以及不传达状态的装饰性英文、头像和徽标。面板采用中文功能标题；颜色用于区分物体、坐标轴、选中状态和依赖状态。保留技术名词、坐标轴符号和必要单位，关键数据不使用过小文字。

主视区仅保留 **2D 视图、3D 视图**：2D 显示首帧与分割结果；3D 统一承担点云浏览、物体轨迹编辑、动态场景预览和相机录制。3D 可切换“自由观察”“跟随相机”，在同一时间轴上播放物体与相机轨迹。内部 4D 时序表示与资产继续保留，不再使用独立 4D 标签；相机录制仍依赖有效的动态场景。副面板按“项目 → 物体控制 → 相机控制 → Diffusion 生成”上下排列，生成面板可独立收起。

页眉的太阳／月亮按钮切换浅色和深色，选择保存在本浏览器；未选择时参考系统主题。界面主题不改变参考图、mask、物体标识色或导出 PNG。点击物体卡片标题独立展开／收起，可多张同时展开，也可全部收起；展开时选中对应物体，收起时保留选择和数据。

## 体验顺序

1. **项目、首帧与分割**：新建项目，导入首帧，在「重建与分割」上传图片并提交 Depth Pro；首次成功结果自动准备点云，可直接切换 3D View。使用正负点击或框选提交 SAM2，选择候选、填写名称和描述后点击「添加物体」；关联完成自动加入物体控制面板，待处理定义支持刷新恢复。替换已有场景仍需手动确认。
2. **选择正面**：切到 3D，查看物体中心的六向参考轴，点击右侧卡片的同色面按钮，或直接点选 bbox 面。当前轴表示 bbox 参考系；所选面定义物体局部 +X，物体初始中心和 bbox 面名称保持不变。选中对象显示紧凑轴名，所有对象的轴与“包围盒与参考轴”开关同步。
3. **物体运动**：点击“预设”体验直线、弧线、升高或环绕，也可以点击卡片“录制”预选目标。此时进入视角控制仍是自由观察；点击底部“开始录制”才准备物体控制器并倒计时。未运动对象明确设置“静止”。
4. **动态场景**：构建或更新随时间变化的场景，在 3D 中播放和拖动时间轴。每个物体独占一行；物体轨迹、时序或初态改变后，派生动态场景需要更新。
5. **相机运动**：动态场景就绪后，在同一 3D 视区录制相机，恢复首帧相机位置、旋转及画幅后开始。相机独占一行，可切换自由观察和跟随相机回放；预设仍需首点对齐。
6. **保存、生成与复用**：结束录制后自动保存本机草稿。完成条件导出后填入生成面板，检查参数并提交推理。项目面板的保存／导出入口可保存集群快照、下载完整包或导出到集群。删除按钮将项目移入恢复记录，不取消任务；从「导入／恢复」找回项目。

## Diffusion 生成

1. 展开副面板底部的“Diffusion 生成”，选择已启用的 SymphoMotion 多 GPU 模型分片配置。查看“模型说明与输入要求”，把示例路径替换为 CE 上已有的模型、权重、配置和条件 CSV。实际输出由后端固定到当前项目的独立作业目录。
2. 在“新名称”中填写名称，使用“新建”“复制”或“重命名”管理项目运行配置。每个项目、每个模型分别保存这些配置，切换后恢复对应参数和命令。
3. 修改参数输入框即可更新命令；也可直接编辑“推理命令”，解析后输入框随之更新。引号未闭合、未知参数或数值不合法时保留草稿并显示错误；可用“从参数重建命令”恢复。这里表示内层推理进程的参数，Slurm 包装由单独配置生成。
4. 在 Slurm 配置中填写 `ENVNAME`，默认 `base`，不加 `ENVNAME=` 前缀。展开 Bash 脚本区域，编辑内容，或导入自己的脚本；默认文件名为 `job.gpu`，可下载保存。初始脚本采用用户给定的配置，示例见 [job.gpu](examples/job.gpu)。
5. 查看只读的完整提交预览，例如 `sbatch job.gpu ENVNAME=base python3 infer.py …`。环境名、脚本文件名和模型参数变化会自动更新此预览。脚本与环境随每份命名配置保存和复制；浏览器不执行 Bash，也不把任意脚本反向解析成模型字段。
6. 无 CE 连接时仍可“导出请求”，保存校验后的模型参数、内层 argv、完整 sbatch 包装和脚本全文。生成配置也包含在完整原型项目备份中，刷新与重新导入后可恢复。
7. 默认地址为同源 `/api`，直接点击“连接并检查模型”；只有跨源或调试部署才需展开“高级连接设置”修改根地址。只有服务返回 API v2、`slurm_sbatch_v1` 与匹配模型版本，且配置校验通过，才能提交。后端在登录节点调用 sbatch，模型在计算节点运行；任务区域显示真实状态与输出链接。提交结果不确定时，新版请求用原 ID、环境和脚本快照重试；旧 API v1 记录不再直接重试。

自定义模型通过“导入模型定义”读取 JSON。可从 [自定义 profile 示例](examples/custom-model.profile.json) 修改模型 ID、入口、字段与默认值，再导入查看表单和命令模板变化；用“导出定义”保存当前模型 schema。自定义定义随项目备份保存，但 CE 仍需安装相应模型并注册同一版本的 adapter，导入不会安装或部署模型。

API 根地址也可通过仓库 [.env.example](../.env.example) 配置 `VITE_CE_API_BASE_URL`，修改环境文件后重启开发服务，生产部署需重新构建。浏览器保存的非空地址优先于构建配置，二者为空时回退 `/api`。“恢复同源 /api”保存相对路径并断开当前连接，之后重新检查能力；历史任务的服务地址保持不变。配置中只填公开 API 地址，不填 CE 登录凭据。默认值不会自动启动后端或配置代理；接口细节见 [同源连接](slurm-execution.md#同源连接与高级设置) 与 [API v2](slurm-execution.md#api-v2-与兼容性)。

`ENVNAME=base` 是传给作业脚本的第一个位置参数；默认脚本读取它后转发剩余 argv。提交成功只代表 Slurm 已接受作业，不能据此认为视频已完成。脚本中的 `7-00:00:00` 表示 7 天，申请 2 GPU 也不会把现有单进程模型自动改成多 GPU 推理。[Slurm 官方说明](https://slurm.schedmd.com/sbatch.html)

SymphoMotion 的全局提示词来自条件包的 `full_prompt.json`，没有 `--prompt` 参数。已有浏览器轨迹不会自动转换成模型需要的 NPZ 和条件视频；当前可使用 CE 已准备好的条件包。任务结果以链接展示，不自动替换首帧或场景。录制期间锁定生成编辑与提交，已接受的任务继续由 CE 执行。

## 键鼠与录制

在 3D 点击“进入视角控制”启用相对鼠标模式。开始录制按钮也会请求鼠标锁定，获得后才倒数 3 秒。

| 输入 | 行为 |
| --- | --- |
| WASD | 沿当前控制参考相机的局部前后左右方向平移 |
| 鼠标移动 | 偏航／俯仰；俯仰限制 ±89°，不会向主动横滚量累积旋转 |
| Q / E | 独立控制横滚 |
| Shift / Control | 沿当前控制参考相机的局部上下方向平移；不再采用世界升降 |
| 鼠标左／右键 | 不再承担加速或减速功能 |
| 鼠标滚轮 | 进入视角控制后，上滚提高设定平移速率、下滚降低；暂适用于观察与两类轨迹录制 |
| 松开全部平移键 | 立即停止平移；不保留惯性或世界速度 |
| P | 暂停录制 |
| Esc | 退出鼠标控制；录制时自动暂停，倒计时中取消 |

平移速率由设置项给定，同时按下多个平移键时将合成方向归一化，避免斜向运动更快。持续按键时，平移方向随参考相机朝向更新。相机轨迹采用受控相机的局部坐标；用户已选择 D18-B，物体采用绑定物体正面的虚拟相机，W 沿物体局部 +X 前进，Shift／Control 沿该虚拟相机的局部上下方向移动。

滚轮与设置面板共同修改设定速率，默认 0.35 su/s，范围 0.01–8 su/s；每个标准滚动单位上滚乘 1.2，下滚除以 1.2，小幅触控板输入按比例计算。左上角分别显示“设定”和“实际”：不按平移键时实际为 0，滚轮本身不会移动对象。录制时滚轮带来的快慢变化保存于时间戳和位姿；它不改变已有轨迹的播放倍率。尚未进入控制、2D、暂停、倒计时、跟随相机回放及输入框滚动不调速。此速率是会话设置，刷新后恢复默认，不等同于项目文件中的轨迹速度。

观察相机与录制控制器分别维护位姿；卡片预选目标不改变观察相机，也不移动物体。普通探索的俯仰相对场景基准，物体录制的俯仰相对初始虚拟相机基准，因此选择上下表面为正面也保留正确初态。旧版的额外横滚来自连续叠加局部偏航／俯仰旋转，而非透视投影或非正交相机轴；现改为独立维护三个角度、重新合成旋转，仍使用透视相机。

录制状态为：预览 → 3 秒倒计时 → 录制 → 暂停 → 结束保存。录制中不能直接点击结束；暂停后“结束录制”启用，“继续录制”禁用。录制中锁定轨迹时间编辑。项目默认 5 秒，可在时间轴修改项目时长；达到项目终点时自动暂停。Space 保留为冗余停止操作，松键直接停止。旧鼠标按钮加减速和惯性参数已移除；滚轮只调节当前设定速率。

录制与场景采样共用 `performance.now()` 时间基准；首个场景渲染帧的积分步长为 0。屏幕数值约每 35ms 更新一次，这一显示节流不改变场景推进或轨迹采样时间。

物体控制器位于 bbox 中心，记录中心位置及完整旋转。跟随观察视角的偏移不写入物体轨迹。在 3D 中使用全局时间同步回放所有已定义轨迹的物体；观察方式可切换自由观察和跟随相机。

重新录制时，新的样本、时间片段及 PNG 一起替换当前结果，旧轨迹进入历史。卡片、放大图和下载均读取当前结果；预览生成失败则保留暂停状态和本次样本，允许重试“结束录制”。

## 几何人物

人物由一个球体头部和五个方块身体部件组成，作为一个完整实例提供 mask、点云、bbox、提示词与刚体轨迹。默认已分割并标记静止；录制前需选择 bbox 正面。整个人物共用一个控制器，不提供四肢关节或骨骼动画。

已有程序化示例会补充人物并重建首帧／mask 缓存，同时保留已有物体及轨迹历史；重复加载不会重复添加。示例几何版本独立记录，外部图像项目不追加演示人物。

## 并行时间轴

时间轴采用项目全局秒轴。每个已分割物体独占一行，相机独占一行；各行相同时间刻度垂直对齐。静止与未定义运动的物体仍保留行，以状态区分，不把多个物体横向串接成一条轨道。

| 操作 | 行为 |
| --- | --- |
| 拖动秒轴或播放指针 | 改变全局预览时刻，同步更新各对象与相机 |
| 拖动整条轨迹块 | 只改变开始时间，保留路径、源采样和片段时长 |
| 拖动左边界 | 保持结束时间，调整开始时间和时长，对整段轨迹等比例重定时 |
| 拖动右边界 | 保持开始时间，调整结束时间和时长，对整段轨迹等比例重定时 |
| 选中片段 | 显示对象、开始／结束时间、时长及明确命名的速度信息 |
| 键盘及数值输入 | 支持不依赖鼠标的时间调整，以项目帧率为时间步长 |

选中轨迹后可直接编辑底部“开始”“时长”。轨迹块和左右边界可通过 Tab 聚焦：方向键调整一帧，Shift＋方向键调整十帧，Home／End 移到该操作的允许边界。数字输入按 Enter 提交、Esc 取消。项目时长不能短于任何片段的结束时间；片段已占满时轴时，先缩短片段或增加项目时长再移动。

D19-A 已确认：保留源轨迹内相对快慢，整段按比例变速；本轮不加入内部变速点。源采样与原始时长不变，时间安排独立保存。全局时间 `t` 映射为源时间 `clamp((t - start) / duration, 0, 1) × sourceDuration`；开始前保持首位姿，结束后保持末位姿。片段移动不改变速度，伸缩改变整段播放倍率。

播放倍率与平移速度分开标注：倍率为 `sourceDuration / duration`；平移速度使用场景单位／秒，并区分平均值与当前时刻值。平均平移速度为源路径总长度除以片段时长；未标定尺度时不得称为米／秒。

播放定位与轨迹编辑分别处理输入，不再使用透明全区滑块遮盖轨迹。轨道数量增加时允许垂直滚动，标签与内容保持同一行。物体时间安排变化使派生动态场景失效；仅相机时间安排变化不使物体动态场景失效。

| 编号 | 用户选择 | 实现影响 |

## 历史 v0.6 实现边界（以当前工作流与项目管理文档为准）

当前使用 2D／3D 两个视图、独立并行时间轨道、松键停止和滚轮调速。下表区分可用前端能力和仍未接入的计算服务。

| 已实现的交互 | 演示或尚未接入的部分 |
| --- | --- |
| 实时点云、相机／物体位姿控制、bbox 六面选择 | 点云是程序化场景，未运行单图重建模型 |
| 同源参考图、彩色 mask、轮廓缩略图、对象选择和提示词编辑 | SAM 用已有几何分割结果演示，未请求真实 SAM 推理 |
| 物体 SE(3) 轨迹、3D 中的动态刚体预览、相机轨迹、预设与历史 | 不提供非刚体动画或背景补全；最终视频计算需 CE 模型服务 |
| 导入首帧、创建项目、原型项目导入／导出与本地保存 | 本机目录只上传到浏览器；未写入 CE 项目目录 |
| 提示词输入及“使用演示场景”的首帧流程 | 不把示例首帧声称为提示词生成结果 |
| 明确坐标系的轨迹 JSON、相机 K、PNG 预览 | 尚未生成 SymphoMotion 的 NPZ 和条件渲染视频 |
| 独立时间片段、整体移动／伸缩、键盘／数值编辑、速度与源时长标注 | 连续鼠标拖动的 GUI 工具验证范围有限，见文末 |
| 固定 K／FOV／畸变编辑、实际投影、可放大 PNG、保存与刷新恢复 | 非零畸变的 SymphoMotion 导出仍待适配 |
| 模型与命名配置切换、参数／命令双向编辑、自定义 schema 导入、请求导出 | 自定义 schema 不安装模型；生成面板不自动构建上游条件包 |
| ENVNAME、脚本编辑／导入／下载、只读 sbatch 预览与快照保存 | 浏览器只校验基础格式；作业脚本、Conda 环境和 Slurm 资源仍由 CE 检查 |
| 可配置 CE 能力查询、任务提交、状态查询与输出链接 | 新提交需要 API v2 与 Slurm 执行能力；仓库未部署 CE 后端或模型权重 |

本原型 `*.prototype.json` 是可自包含的浏览器备份格式。文档中设计的正式 `project.json` 可导入名称、首帧等基础信息和 generation 扩展；真实 PLY、NPZ 与服务器相对路径的解析仍需后端。原型不把没有实际加载的外部点云标记为 ready。

数据保存在当前浏览器的 `localStorage`，不会同步到 CE；更换浏览器或清理网站数据后无法自动恢复，请使用导出备份。存储容量有限，较大参考图可能超限，界面会提示导出。读取旧 v1 数据时保留原存储键；旧 v2 数据需要修复或示例升级时，先写入独立恢复备份键，配额不足则尝试 IndexedDB 恢复副本，事务提交后才允许覆盖工作区。两种备份均失败则保留旧工作区并提示仅当前会话。IndexedDB 此处仅保存恢复副本；正式服务端原子保存、作业队列和完整分块恢复不属于已实现能力。

未确认细节暂用原型建议值：默认 5 秒时间轴和刚体组合动态场景。升降现已按用户要求使用控制相机的局部方向。bbox 目前为轴对齐的可选面示例，没有完整 OBB 拟合／编辑器；选择 ±Y 面为正面时，既有原型用世界 +Z 作为上方参考，这不代表 D07-bbox／D07-上方已确定。

v0.6 的构建、测试、浏览器检查与 CE 验证限制统一见 [当前验证记录](slurm-execution.md#验证记录)。以下保留既有版本的历史结果，不代表本轮已重新完成所有原生输入验收。

### 历史 v0.5

模型与命令编辑、任务客户端和项目持久化的历史验证见 [v0.5 验证记录](generation-panel.md#验证记录)。

### 历史 v0.4

v0.4 的 `npm run build` 成功，`npm test` 的 **12 个测试文件、75 项测试全部通过**。新增 8 项验证参考轴颜色／中心／六面初态／动态旋转，以及滚轮输入范围、单位归一、比例、限值和松键停止；既有转向、录制、迁移、时间轴、镜头与数据校验回归继续通过。5 份 JSON 示例格式沿用此前通过解析的版本，本轮没有改写。

该版浏览器已检查参考轴、卡片配色和速度 HUD，以及未进入控制时滚轮不修改速度。其余原生滚轮与组合移动的实际覆盖以 [v0.4 验证结果](changes-v0.4.md#验证结果) 为准。

### 历史 v0.3 与 v0.2

v0.3 浏览器已检查两种主题及刷新保留、卡片同时展开与全部收起、预选人物后仍自由观察、人物重复录制后的卡片／放大图／时间片段同步以及刷新恢复。实际步骤及横滚复现结果见 [v0.3 验证记录](changes-v0.3.md#验证记录)。连续按键与鼠标组合运动的原生输入体验仍需用户实际操作确认。

浏览器已检查独立轨道与速度显示：示例物体片段从 5 秒缩到 2.5 秒，倍率变为 2.00×，平均平移速度随之加倍；数值与键盘编辑能独立调整相机，不改变物体片段。在 16 帧／秒的项目中，Shift＋方向键移动十帧即 0.625 秒，Home 恢复起点；右边界的缩短与恢复同步更新倍率。非零 `k1 = 0.08` 的镜头参数已检查实际场景投影、PNG 预览和保存后刷新恢复，随后恢复为零畸变、55° 垂直视场角。

曾观察到单次鼠标伸缩及移动的界面变化，但连续 GUI 拖动测试中，工具未提供完整的按键状态和 pointer capture，因而**连续真实鼠标手势的端到端验证仍不完整**。实现保留标准的指针捕获、释放、取消和失焦清理，不接纳无按键且无捕获的残留移动事件。数值／键盘编辑和纯手势回归已验证；纯函数测试不替代浏览器原生事件验证。

真实模型接口、CE 部署及 SymphoMotion 导出仍未验证。
