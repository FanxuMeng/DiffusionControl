## 已核实的问题

- 当前产物保存在 `var/jobs/<作业 UUID>/outputs`。`job.gpu` 的 `#SBATCH -o out.gpu` 仅表示标准输出日志，后端提交时还会通过 `--output`／`--error` 覆盖日志位置。Depth Pro 和 SAM2 的实际模型产物目录由后端 `--output-dir` 参数指定。
- 用户最新两次 Depth Pro 和一次 SAM2 作业均已成功。最近场景包含 301,176 个完整点；页面仍提示先重建，原因是成功作业未自动绑定，只有作业列表底部的「应用重建」会设置 `geometryReady`、相机标定和 `sceneJobId`。
- 左上角项目名称和下拉箭头是静态 `div`，没有选择行为。缩略图下方项目名称没有编辑入口。
- SAM2 候选按钮只记录选中索引；还需手动提交关联、等待、再到作业列表点「加入场景」。名称与描述取自应用时的输入框，未绑定提交时的物体定义。

## 项目持久化目录

新任务（Depth Pro、SAM2、点簇关联、条件导出、Diffusion 生成）统一使用：

```text
DiffusionControl/
  projects/<稳定项目 ID>/
    project-info.json              # 项目标识、最近保存／提交时的显示名称
    jobs/<作业 UUID>/
      request.json                 # 原始提交，不因目录迁移或重命名改写
      execution-plan.json
      submission/job.gpu
      submission/task.json         # 工作流任务快照
      stdout.log
      stderr.log
      outputs/                     # 模型直接写入的目录
      outputs.json
  var/
    jobs.sqlite3                   # 单进程作业及项目快照索引
    assets/                        # 按内容去重的规范化首帧
    projects/                      # 版本快照、完整交换包、上传暂存、后台操作
    migrations/                    # 目录迁移报告及变更文件恢复副本
```

`projectsRoot` 默认是项目根下的 `projects`，配置只能指向 DiffusionControl 内目录。正常项目 ID 直接用作目录名；旧格式的特殊字符 ID 使用哈希目录名，并在 `project-info.json` 中保留原 ID。目录从稳定 ID 生成，不随名称变化，也不使用可编辑名称拼接文件路径。拒绝路径穿越和符号链接。前端展示服务端返回的实际产物路径。

历史迁移仅在服务优雅停止、确认无运行中作业和文件交换操作后执行。保留数据库及待改写文件的恢复副本，先验证目标目录和已发布文件，再移动作业目录；更新输出目录、条件 JSON／CSV 和嵌套条件包中的路径，重新发布文件校验清单。作业 ID、原始请求、Slurm 信息、历史执行命令保持不变，API 下载地址不变。保存过的项目快照如含旧路径，以新版本保存并保留删除标记；旧版本继续作为历史记录。浏览器中手动填写的旧绝对文件路径需改用任务面板显示的新路径，或重新点「填入生成配置」。

完整项目包继续兼容 v1；导入按每个作业的原输出目录及历史别名映射到新位置，兼容此前 `var/jobs` 的包。恢复依旧不会执行代码或提交模型任务。项目删除继续保留作业和产物。

## 前端状态和交互

物体删除及其轨迹、点云、异步关联和导出联动见 [物体控制面板：删除物体](object-deletion.md)。

3D View 的可视化包围盒编辑与相机轨迹删除见 [3D 包围盒编辑与相机轨迹删除](bounding-box-editor.md)。

1. 项目名称通过缩略图旁的编辑按钮修改；Enter 保存、Escape 取消，拒绝空白及超过 200 字符的名称。同步更新本机项目列表、页眉和后续提交名称；集群快照仍通过显式保存更新。
2. 左上角改为鼠标和键盘均可操作的项目选择器，调用与项目卡片相同的切换逻辑。切换重置选择、时间轴、录制目标和 SAM2 提示，异步任务结果按项目 ID 隔离。
   浏览器回归必须覆盖「切换到另一项目再返回 → 重命名 → 选择候选 → 输入定义」。重建面板使用稳定组件实例，切换时显式清空候选、输入草稿和结果错误；异步完成时校验当前项目和首帧，避免复用失效的事件状态。
3. 首次匹配当前首帧的成功 Depth Pro 结果自动绑定相机和点云，刷新或重新打开项目也可发现已完成作业。当前已有场景时不自动切换到其他重建；替换有物体或轨迹的场景须确认。3D View 显示加载／错误状态，避免用「未重建」描述已成功但正在读取的产物。
4. 首次自动绑定不打断用户正在进行的 SAM2 标注；用户点击 3D View 即可预览。录制／项目交换期间暂缓自动应用。
5. SAM2 候选选中后显示明确反馈，填写名称／描述后点击「添加物体」。缺少场景或候选时显示原因；关联请求沿用全局 sbatch 脚本和独立 ENVNAME。
6. 提交前把物体定义、候选、关联请求 ID 保存到项目工作流状态；物体面板立即显示待处理卡片。成功后自动建立点簇、初始 AABB 和物体实例，无需手动应用。刷新、重新打开项目、重复轮询均不会重复添加物体或重复提交任务。
7. 关联失败／取消保留可见状态和原定义；网络提交结果未知时用原 requestId 确认。场景／首帧／已有关联物体集合改变后拒绝应用旧结果，保留产物用于排查。旧版本手动提交的关联结果仍提供「加入场景」。
