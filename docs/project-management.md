# 项目管理与本地／集群交换

修订：2026-09-10。本轮先记录设计，再修改代码。用于正式生成测试的项目面板需要新建、打开、删除、导入、导出与明确的保存位置；现有模型、Slurm、轨迹及重建数据契约继续沿用。

后续修订：推理作业及产物改为 `projects/<稳定项目 ID>/jobs/<作业 ID>`，历史已完成产物按用户授权迁移；`var/projects` 继续用于快照和交换包。项目名称编辑、页眉选择器、重建自动绑定和分割物体自动关联详见 [目录与交互修复](workflow-usability-and-storage.md)。

## 改造前的问题

- 浏览器首次访问、空项目列表或恢复失败时均回退到 `createDemoProjects()`，删除最后一个项目后会重新出现示例。
- 项目面板没有删除入口。当前编辑器假定始终存在 `projects[0]`，需要真正支持没有项目的状态。
- `*.prototype.json` 保存配置及同一服务器的资产／作业引用，不是包含真实点云、掩码、条件和生成产物的可迁移包。
- 集群端已有资产与作业存储，但没有项目保存／打开接口；浏览器中的母路径只是文字，不能据此读写任意服务器文件。

## 已明确的行为

1. 正式入口不再自动创建示例，也不提供「创建演示首帧／使用演示场景」入口。旧浏览器工作区中的示例从项目列表移除前保留恢复副本；真实导入项目保留。程序化示例函数可继续供历史迁移和回归测试使用。
2. 项目列表允许为空。首次进入与删除最后一个项目后显示新建／导入入口；没有活动项目时不挂载三维场景、工作流或生成任务面板。
3. 项目项提供独立删除按钮，操作前显示目标项目名与删除范围。录制、切换或导入尚未完成时避免对错误项目操作；异步结果始终按项目 ID 应用。
4. 本地入口通过浏览器文件选择／下载；集群入口由受认证的同源 API 读写。本轮管理根目录为 `DiffusionControl/var/projects`，不访问额外目录。界面区分「本机已保存」与「已保存到集群」，不把浏览器自动保存称为集群同步。
5. 集群保存采用版本检查、同目录临时文件和原子替换，避免两次保存静默覆盖。路径由服务端生成或在管理根内解析，拒绝路径穿越及符号链接。沿用现有 Host／Origin／令牌认证。
6. 删除和导入后的活动项目、选择物体、视图、时间轴与录制状态一起重置。旧格式仍按现有迁移／校验规则读取，不将缺失几何资产标记为 ready。

## 用户确认与完整包设计

用户选择完整项目包，并确认删除仅移除项目、保留恢复副本、保留作业及产物，运行任务继续执行。

- 使用版本化 `.dcproject.zip`：项目 JSON、首帧资产、该项目已完成作业的请求／元数据／产物和 SHA-256 清单。模型权重、Conda 环境、访问令牌不打包；模型路径作为配置保留。旧 JSON 仍可导入，但界面明确它依赖原服务。
- 保存到集群的是带版本的项目快照；本地下载和集群导出使用同一完整包。集群导入从受管理的包列表选择，包文件实际位于 `var/projects/packages`，用户也可将现成包放入此目录后刷新列表。
- 手动放入集群目录的包名支持中文和空格，须以 `.dcproject.zip` 结尾且 UTF-8 文件名不超过 240 字节；拒绝目录分隔符、控制字符及路径穿越。损坏的 ZIP 或缺少清单时返回可读错误，不替换现有项目。
- 导出项目涉及的任务须已结束，尚未确认的提交须先在任务面板处理；不把半写入的模型结果纳入完整包。此约束不影响删除，删除时任务继续运行。
- 导入保留稳定项目／作业／资产 ID，恢复同一项目而非暗中复制；已有同 ID 作业必须与包内原始请求和产物一致，否则拒绝。跨服务恢复时将管理根及导出 CSV／manifest 中的服务器路径转换为新根，重建发布清单和只读状态。已完成作业以终态恢复，导入绝不执行打包的脚本或自动提交推理。
- 导入包先校验全体路径、条目数、展开大小、压缩格式和哈希；拒绝符号链接、重复路径、路径穿越、缺失依赖与不受支持格式。通过前不替换当前项目。大文件上传分块写入项目内暂存目录，打包／恢复在后台操作中执行，界面轮询进度。
- 删除前将本机项目写入可恢复存储；服务器快照转入回收列表，可从集群入口恢复。服务器没有保存过的本机项目仍可删除并本机恢复。集群快照与本机编辑是显式保存关系，不实现自动多人同步。

覆盖空列表初始化、示例迁移备份、删除活动／非活动／最后一个项目、集群保存／打开／版本冲突，以及资产清单与哈希、缺失文件、恶意 ZIP 路径、导入后的引用绑定及重新导出。真实 HTTP 测试仅使用专门的验证项目；不提交 GPU 作业，不删除用户原有项目或先前模型测试结果。

## 使用方式

1. 刷新当前 `http://10.27.130.15:5192/login` 入口。首次访问显示空工作区；旧示例从正式列表移除，已有真实项目保留。
2. 新建项目后导入首帧并开始重建。浏览器自动保存只保存在当前浏览器；通过「保存／导出 → 保存项目到集群」保存可从其他电脑打开的快照。
3. 项目卡片的删除按钮将项目移入回收记录。可在「导入／恢复」找回本机记录或集群快照。作业和产物保留，正在运行的任务继续执行。
4. 任务全部结束后，通过「导出完整包到本地／集群」生成 `.dcproject.zip`。本地下载也会在服务器保留同一包；导出不会替代显式保存集群快照。
5. 通过「从本地导入」上传完整包，或将包放入 `var/projects/packages` 后刷新并导入。稳定 ID 相同的项目需要确认恢复为新版本，旧快照保留；作业 ID 冲突且内容不同则拒绝导入。

本轮集群文件入口限制在上述管理目录，不提供任意服务器路径浏览。空项目可直接打包；包含真实产物的项目须连接原服务才能导出完整包。旧 `.prototype.json` 仍可恢复配置及原服务器引用。

## HTTP 与存储

接口沿用已有登录会话及 Host／Origin 检查，均位于 `/api/projects` 下：

| 方法与后缀 | 用途 |
| --- | --- |
| `GET /` | 快照、回收记录、包列表及管理根 |
| `POST /save` | 按 `revision` 保存项目快照，冲突返回 409 |
| `GET /snapshots/{key}` | 读取快照 |
| `POST /snapshots/{key}/delete` | 按版本软删除 |
| `POST /export`、`POST /import` | 返回 202 和后台文件操作 ID |
| `GET /operations/{id}` | 查询排队／运行／成功／失败及结果 |
| `POST /uploads` | 顺序上传分块，校验偏移量；最后一块发布为包 |
| `GET /packages/{name}`、`GET /packages/{name}/info` | 下载包、读取项目标识与当前快照版本 |

快照保存在 `var/projects/snapshots/<项目 ID 的 SHA-256>/<版本>.json`，最新记录存入现有 SQLite 的 `projects` 表。完整包在 `packages`，上传暂存与后台状态分别在 `uploads`、`staging`、`operations`。这些目录和作业产物都应纳入服务器备份。

包文件最多 4 GiB，解包总量最多 8 GiB、20,001 个条目，项目 JSON 最多 48 MiB；上传每块最多 2 MiB。文件操作使用一个后台线程，最多同时接受四个排队或执行中的操作。服务重启会将未完成文件操作标为失败，需手动重试；不会自动重提推理。回收副本写入失败时保留原项目，并在界面显示错误。
