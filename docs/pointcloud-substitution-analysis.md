# 前端点云操作能否替代 SymphoMotion pointcloud.py

调研日期：2026-09-09。范围：当前本地源码静态分析及 PyTorch3D 官方 API 文档核对。

后续实施说明：下文保留实施前的调研结论。其后已按用户确认新增真实深度、SAM2、点 ID 关联、动态点云条件导出和前端链路，代码与验证状态见 [重建工作流](reconstruction-workflow.md)。Three.js 视口继续用于交互，正式条件使用计算节点的专用导出器。

- DiffusionControl：基于 `cc9d4a6818cef328cf8b6d8a494740a8de5d2e70` 的当前工作区，包含尚未提交的后端建设变更。
- SymphoMotion：`bf9af6666c0f8cbb594e64f165be79b44c962763`，本次仅查看源码。
- 本次未修改应用代码或推理环境，未运行 GPU 推理，也未进行两种渲染器的像素对照或性能测试。

## 结论

**当前前端不能直接替代 `pointcloud.py`。现有交互、物体刚体变换、时间轴和相机控制可以继续使用；真实点云的剔除与模型条件导出仍需补齐。**

如果替代范围只包含“根据深度边缘与指定 mask 删除点”，算法可以在浏览器实现，并不天然依赖 Python 或 GPU。但当前前端没有实现这些计算，也没有接入所需的真实深度图、完整分割 mask 和来源像素索引。

如果替代范围包括整个 `point_rendering()`，还需要完成相机约定转换、点光栅化与合成、空洞 mask 生成及首帧处理。当前 Three.js 交互视口的截图不能直接当作已兼容的模型条件。模型 loader 通过文件读取条件，不要求文件必须由 PyTorch3D 生成，因此完整浏览器替代在接口层面可行；画面与模型效果是否达到要求仍须验证。

## 2. pointcloud.py 中“剔除”的准确含义

源文件：[`SymphoMotion/src/pointcloud.py`](../../SymphoMotion/src/pointcloud.py)，主要入口为第 75 行的 `point_rendering()`。它接收已经生成的深度与可选 SAM mask，**自身不执行深度估计或 SAM 分割推理**。

### 2.1 先压缩远处深度

默认 `contract=8.0`，令 `m = median(depth) × contract`。对 `depth > m` 的位置执行：

```text
D' = 2m - m² / (D + 1e-6)
```

其他位置保持原深度。正中位数情况下，极远点被压向约 `2m`。这是修改三维几何距离，不是删除远点，更不等于视口 far 裁剪或雾效果。后面的逆深度边缘检测与反投影都使用修改后的深度。

### 2.2 删除深度不连续处的点

第 107–108 行计算 `disparity = 1 / (depth + 1e-7)`。第 19 行的辅助函数先做全图 min/max 归一化，再使用 Kornia Sobel（`normalized=False`）计算梯度：

```text
gradient = sqrt(gx² + gy²)
remove_boundary = exp(-10 × gradient) < sobel_threshold
```

`point_rendering()` 默认阈值是 `0.35`；独立调用 `get_boundaries_mask()` 时其默认值是 `0.3`。这是深度断层边缘过滤，不是通用的统计离群点、半径邻居或连通域过滤。

### 2.3 删除指定 mask 对应的点

第 110–115 行用 `(x+0.5, y+0.5)` 像素位置反投影，并按图像顺序展平点和颜色。第 119–133 行执行：

```text
remove = remove_boundary OR (sam_mask == True)
remaining_points = points[NOT remove]
remaining_colors = colors[NOT remove]
```

这里每个点和源像素一一对应，所以不用通过三维 bbox 猜测归属。mask 需要符合接口的 0/1 或布尔约定；不能直接把 0/255 图或概率值传入并期待同样行为。

函数删除指定区域，但没有返回被删除物体的局部点集、点 ID 或物体轨迹。要将这些点作为可移动物体保留，需要适配器在过滤时另行保存对应集合。

### 2.4 渲染剩余静态点云并输出空洞

第 135 行将同一份点云复制到 F 个视角，并没有逐帧施加物体运动。第 32–56 行使用点到像素的距离权重 `1 - d²/r²`，随后经 `AlphaCompositor` 合成。

PyTorch3D 的半径以 NDC 为单位，每像素可以保留多个按深度排序的点，再按 alpha 累积颜色。这些规则与当前前端的普通点材质不同。实际 `raster_settings` 由调用方传入；当前仓库没有找到调用处，不能把库的默认半径或 `points_per_pixel` 当作该项目已确认的运行参数。[点光栅化文档](https://pytorch3d.readthedocs.io/en/latest/modules/renderer/points/rasterizer.html)、[颜色合成文档](https://pytorch3d.readthedocs.io/en/latest/modules/renderer/compositing.html)。

第 164 行定义 `render_mask = (zbuf[..., 0:1] == -1)`：

- `1`：该像素没有点覆盖，是空洞。
- `0`：有点覆盖。
- 首帧 RGB 强制替换为输入参考图，首帧 mask 强制清零。

全零深度或最终保留点数不超过 8 时，其余帧为零 RGB、全一 mask，首帧仍按上述约定处理。因此 render mask 与“物体属于哪个实例”的 SAM mask 是两种数据。

## 3. 当前前端看起来类似，但尚未完成的部分

### 3.1 点云与 mask 来自已知的演示网格

`sceneGeometry.ts:96` 的 `sampleGroup()` 按三角形面积采样，并从材质色、法向和随机扰动生成颜色。第 105 行跳过退化三角形只是采样前的几何检查，不是深度边缘删点。

`createSceneGeometry()` 从一开始就分别建立背景和各个物体。`SceneViewport.tsx:125` 的 mask 预览通过重新着色已知物体网格、应用深度遮挡，再裁剪成 192×192 彩色缩略图得到。`App.tsx:207` 点选后设置 `segmented=true`，没有从真实深度点云中删除或提取点。

这条路径是“已知物体几何 → 点云/预览 mask”。实际重建需要“参考图 + 深度 + 实例 mask → 点云及实例归属”。`model.ts:402` 还明确拒绝 `demoScene === null` 且 `geometryReady === true` 的项目；真实外部几何尚未接入。

演示网格可以包含背面和被遮挡的完整背景；单视角深度只有当时可见的表面。演示中物体移开后露出房间，不能证明系统已经补全真实场景的遮挡区域。

### 3.2 显示裁剪不会删除源点

`captureProjection.ts:37` 为畸变投影计算有效射线范围，第 64 行将超出范围的顶点移出画面；第 54 行还关闭了 Three.js 的对象级 `frustumCulled`，以免理想视锥误剔除畸变后可见的几何。

这些操作以及常规深度遮挡、near/far 裁剪，只决定当前视角的显示结果，不会按深度边缘或 SAM mask 改写源点数组。隐藏点可以在换视角后再次出现；从点集删除则会影响后续全部视角。

### 3.3 操作和轨迹逻辑可以复用

`SceneViewport.tsx:234` 已将对象位姿施加给对应点云分组，`timelineModel.ts:31` 与第 46 行分别处理 clip 时间映射、位置线性插值和四元数球面插值。真实点云只要提供正确的对象分组、局部坐标、初始位姿和稳定点身份，就可以复用这类交互逻辑。

但当前 `SceneObject` 主要保存形状、bbox、位姿、轨迹和 `maskPreview`，没有持久化真实点 ID、来源像素、深度与实例标签。接入时需要扩充资产与索引契约。

### 3.4 不能用当前视口截图作为条件导出

视口启用了 sRGB 输出、ACES 色调映射、曝光及雾，还包含网格、轨迹和编辑标记。当前点材质也没有实现上游的距离权重及多层点合成。正式导出需要单独的渲染路径，并从实际点覆盖生成空洞 mask，不能通过“像素是否为黑色”判断空洞。

投影适配还要处理三个已确认的差异：

1. 前端以整数像素中心定义 K，并在投影矩阵中处理 `+0.5`；上游反投影直接取半整数像素位置。必须统一 K 对应的像素中心约定后对照投影结果。
2. 前端通过 `BASIS` 转换 Three.js 显示坐标；上游翻转 c2w 的前两列再传给 PyTorch3D。应分别从公共 OpenCV 坐标转换，不能直接叠加两套符号变换。
3. 前端支持 Brown–Conrady 五参数畸变，`pointcloud.py` 未接收畸变参数。非零畸变需显式适配或去畸变，同时更新图像、mask 和 K。

## 4. 替代这个文件，不会自动接通推理

本次在 SymphoMotion 仓库检索 `point_rendering` 与 `get_boundaries_mask`，仅找到该文件中的定义和内部调用，未找到仓库内调用它的预处理入口。这不能排除仓库外脚本或动态调用。

实际可确认的推理路径为：

```text
infer.py:281
  → src/dataset_from_npz.py:38 的 load_dataset()
  → 读取已存在的 render_output/render_with_2d_bbox.mp4
  → 读取已存在的 render_output/render_mask.mp4
  → 读取 spatialtracker2.npz 的相机与物体点集轨迹
```

`pointcloud.py` 自身没有 MP4/NPZ 导出，也没有联合二维物体框生成。完整框渲染样式和可能的后续 mask 处理，还需要与正式样例核对，不能只凭文件名自行确定。

当前 DiffusionControl 后端 `adapter.py` 校验已有条件包并组织推理命令，本轮已完成的生成/Slurm 后端不包含条件导出。前端 `App.tsx:423` 也明确标记模型条件包尚未实现。

另一个独立适配问题是：`dataset_from_npz.py:41` 会调整图像尺寸，但第 89–92 行对 K 的所谓调整只是原值赋回。导出器需要提前生成与最终分辨率一致的 K，不能依赖 loader 自动缩放。

## 5. 建议的接入方式

建议继续使用现有前端做交互，下一步补齐共享真实几何与条件导出，而非重写编辑器。以下是建议，尚未实施，也不改变现有部署架构决定。

1. 深度/SAM 等上游服务输出参考图、深度、K、参考 c2w、完整实例 mask，并记录分辨率、深度定义和版本。深度必须明确是相机 Z 深度还是射线距离。
2. 建立稳定的 `point_id ↔ 来源像素 ↔ XYZ/RGB ↔ instance_id` 映射。边缘过滤、背景点、物体点都引用同一份源数据，避免物体移动后原地仍保留一份。
3. 前端加载真实点云，继续做选择、刚体操作、相机和时间轴编辑。浏览器可对显示点降采样，但保存/导出必须保持与完整点集的索引对应。
4. 后端适配器复用或适配 `pointcloud.py` 的预处理、背景渲染和空洞语义，再补充物体点轨迹、经验证的 bbox 条件和文件导出。计算任务按现有架构调度到计算节点。

如果希望删点本身全部在浏览器执行，可把深度压缩、Sobel、mask 合并和点索引筛选抽成独立模块，通过 Worker 或 GPU 实现。保存原始资产版本、算法参数及删除点 ID/位图，后端校验后直接消费，避免丢失可复现依据。若要求结果与上游一致，需对齐 Sobel 核与边界填充、中位数定义、运算精度及阈值边界。

如果进一步要求全部条件渲染也在浏览器完成，需要新增独立离屏输出、点覆盖及深度合成、RGB 与 mask 帧导出、稳定点集轨迹和 MP4/NPZ 打包。可以做功能兼容的新渲染器，也可以以复现上游数值为目标；两者的验收要求不同。具体路线应在开始实现前确认。

## 6. 如何验证“已可替代”

| 验证层 | 对照方法 | 必须覆盖的问题 |
| --- | --- | --- |
| 剔除结果 | 同一 RGB/depth/K/mask 分别走两端，比较保留的原始点 ID | 深度平面与断层、mask 边界、全零深度、极少点、阈值附近的数值差异 |
| 几何 | 比较压缩后深度、反投影 XYZ、物体分组和每帧坐标 | 像素中心、深度定义、矩阵方向、前后景遮挡、重叠实例与稳定点身份 |
| 图像与空洞 | 固定输入和光栅化参数，先比较编码前覆盖 mask，再比较统一色彩空间下 RGB | 点半径、遮挡、画外点、空洞极性、黑色实体、首帧覆盖；报告 mask 差异与 RGB 误差 |
| 模型文件 | 用实际 loader 读取导出包，检查形状、数值、帧数、K、实体映射和编码后 mask | 相机/物体公共时间轴、缩放后的 K、轨迹坐标、bbox 条件约定 |
| 推理效果与性能 | 在计算节点用相同模型、提示词、种子和采样设置做对照；单独测浏览器开销 | 相机运动、物体运动及联合运动，显存/内存、导出耗时与跨浏览器表现 |

现有前端几何测试验证的是演示采样与交互相关约束，没有证明真实深度剔除、条件 mask 或模型输出与上游等价。本文结论属于代码兼容性判断，尚无上述实验的通过结果。

## 7. 复用上游时的实现注意

上游函数不宜未经封装就作为长期任务服务：深度压缩使用原位赋值；一般 NaN、负深度等输入没有完整的显式校验；渲染异常分支向当前目录写 debug tensor 后没有立即退出，可能继续访问未赋值结果。实施时应处理输入副本、参数校验和明确的错误传播，并把调试输出限制在每作业目录。

这些问题不改变本文对剔除语义的判断，也不意味着浏览器实现天然更合适。最终应以共同的数据契约、可复现参数和对照结果决定替代范围。
